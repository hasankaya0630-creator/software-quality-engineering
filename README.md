# Software Quality Engineering Portfolio

## Overview

This repository showcases my work in software development, software testing, and quality assurance. It includes Java-based contact management functionality, unit tests, and reflections on software design, functionality, security, and user needs.

## Portfolio Artifacts

The repository will include the following artifacts:

* **Contact.java:** Defines the contact data model and its required attributes.
* **ContactService.java:** Implements operations for managing contact records.
* **ContactTest.java:** Contains unit tests for the Contact class.
* **ContactServiceTest.java:** Contains unit tests for the ContactService class.
* **Project Two Summary and Reflections:** Documents my approach to software testing, quality assurance, and professional development.

## Reflection Questions

### 1. How do I ensure that my code, program, or software is functional and secure?

I use systematic testing to verify that software behaves as expected and meets its requirements. Unit tests help me check individual components, identify defects, and confirm that important functions work correctly. I also test boundary conditions and invalid inputs to ensure the program handles unexpected situations appropriately. To improve security, I validate user input, prevent unauthorized changes to data, and consider potential vulnerabilities during development. Reviewing and updating code helps maintain its reliability and security.

### 2. How do I interpret user needs and incorporate them into a program?

I begin by identifying the user's requirements and determining what the software must accomplish. I translate those requirements into specific functions, rules, and test cases. For example, a contact management application must store valid contact information and allow users to manage contact records according to the stated requirements. I use testing to verify that the implementation meets those needs. This approach helps ensure that the finished program is useful, reliable, and aligned with user expectations.

### 3. How do I approach designing software?

I approach software design by breaking a problem into smaller, manageable components. I identify the responsibilities of each class, define the data and operations needed, and consider how the components will interact. I aim to create code that is organized, readable, reusable, and easy to test. I also consider error handling, security, maintainability, and future improvements. Testing throughout development helps me identify design issues early and improve the overall quality of the software.

## Professional Development

These projects demonstrate my developing skills in Java programming, unit testing, debugging, software design, and quality assurance. They also reflect my commitment to creating software that meets user requirements and follows sound engineering practices.
